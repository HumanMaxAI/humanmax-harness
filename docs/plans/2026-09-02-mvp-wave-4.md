## Order of work

1. **G10 — `add tool` documentation stub (this session).** `addTool` already writes declaration, `src/tools.ts`, a gateway test, and the agent registry entry. Add `docs/tools/<id>.md` in the same plan. Ownership: `user-owned`. Stub states effect class, gateway requirement, that `.humanmax/` is canonical, and that Harness is not certification. Dry-run must list the file and write nothing. Apply must update `generator.lock`. Do not change the default `create` tree (tree-snapshot stays stable).
2. **G18 — contract fixtures.** Add an incompatible-`apiVersion` fixture and at least one boundary fixture (empty string, exact size/depth limit already in `yaml.test.ts` counts for YAML; document-level version mismatch is the missing validate test).
3. **G19 — `NEEDS_HUMAN_REVIEW`.** Emit that state from Core for a constructed fixture (not the default generated project). Default `check` must remain non-failing for a clean Preview project.
4. **G13 — enforcement-adapter conformance suite.** Public tests a third-party adapter can import or copy: undeclared tools fail closed; effectful tools cannot skip the gateway; deny-all-production never allows an effectful action; installing an adapter cannot claim `enforced`.
5. **G21 — offline `check`.** Prove `humanmax check` on a generated fixture with network blocked (`NODE_OPTIONS` / `https_proxy` / sandbox). Missing evidence stays `UNKNOWN`.
6. **G32 — threat model.** Short `docs/guides/` note: local-first, no source upload, gateway, deny-all-production, pack digest. Not certification.
