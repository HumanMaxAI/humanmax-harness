# Plan: Publish Preview 0.2.0 to npm

Date: 2026-10-30. Role: release coordinator.
Intent: [npm release request](./2026-10-30-npm-preview-020-intent.md).

## Files and ownership

The human authorized takeover of the contracts, core, runtime, generator, CLI, docs, and CI lanes for this release. Edit only release metadata and verification files in those lanes.

- All eight `packages/*/package.json`: version 0.2.0 and internal dependency ranges ^0.2.0.
- `package-lock.json`: regenerate through npm. Coordinate this shared-file update in this release task.
- `packages/project-generator/src/dependencies.ts`, `src/generate.ts`, `src/generate.test.ts`, and `README.md`: update emitted versions, generator identity, and version expectations.
- `packages/cli/verification/distribution.mjs`: install all eight candidate tarballs, use candidate entry versions, and verify the full 0.2.0 dependency graph.
- `README.md`, `CHANGELOG.md`, and a dated release verification note in `docs/reviews/`: document the Node 26 migration, checks, and publication state.
- `scripts/publish-workspaces.mjs` and its tests only if an observed release failure requires a minimal fix. Keep the main-only OIDC workflow and quality gates intact.

## Procedure

1. Commit this plan and intent before implementation.
2. Update existing generator test expectations to the 0.2.0 output. Confirm that the test fails with the previous version pins.
3. Update package versions, internal ranges, generator pins and identity. Update the packed-distribution verification to serve all candidate packages.
4. Regenerate the lockfile with npm. Run build, tests, typecheck, audit, scaffold verification, packed-distribution verification, and the release dry run.
5. Review the diff for behavior, constraints, and security. Record verification output and remaining limits in a review note.
6. Push a release branch and create a PR. Follow the repository review policy. Do not create an approval for the human.
7. After permitted integration, use the existing main push workflow to publish through npm Trusted Publishing. Inspect publication logs and all eight exact versions.
8. Install the public entry packages in a temporary directory. Generate a project, run npm install/ci, build, typecheck, tests, and the project-pinned CLI. Verify Node requirements and dependency versions.
9. Tag the published release commit as v0.2.0 after registry and installation verification. Remove this task's lane claims when merged.

## Proof

- `npm run build`, `npm test`, `npm run typecheck`, `npm audit --audit-level=low`, `node scripts/check-scaffold.mjs`, and `git diff --check`: exit 0.
- `node packages/cli/verification/distribution.mjs`: PASS, exit 0, with eight real candidate tarballs.
- `node scripts/publish-workspaces.mjs --dry-run`: eight would-publish lines before release.
- Main CI: workspace, generated-project, both CodeQL jobs, and publish succeed.
- Public npm: all eight exact 0.2.0 versions exist, with Node >=26; installed commands and generated project checks succeed.

## Risks and recovery

Publishing is immutable. Do not reuse an existing version or claim that skipped packages were newly published. If publication is partial, stop on the failure and rerun the corrected release path; the script skips existing exact versions. Existing 0.1.x releases remain available for Node 22 users. Do not unpublish packages or change an old version. No pack version, API identifier, or result-state change is part of this release.
